# ЛР 21 — Внедрение паттерна MVVM

## Основная идея
Переход от прямого управления данными в UI к архитектуре MVVM (Model-View-ViewModel) с использованием **StateFlow** и **UDF** (Unidirectional Data Flow).

## Что было сделано:
1. Создание UiState: Все состояния экрана (список задач, флаг загрузки, ошибки) объединены в единый неизменяемый объект `TasksUiState`.
2. Рефакторинг ViewModel:
    * Внедрен `StateFlow` для реактивного обновления интерфейса.
    * Реализована инкапсуляция: состояние изменяется только внутри ViewModel через `MutableStateFlow.update`.
    * Добавлена обработка событий пользователя через единую точку входа (метод `onEvent`).
3. Обновление Compose UI:
    * Экран `TasksScreen` переведен в разряд "пассивных" компонентов.
    * Использован `collectAsStateWithLifecycle()` для безопасного сбора данных с учетом жизненного цикла Activity.
    * Реализована декларативная отрисовка состояний (загрузка/ошибка/контент) через оператор `when`.

## Выводы по работе:
* Изоляция логики: Бизнес-логика полностью отделена от кода верстки, что упрощает тестирование.
* Стабильность: Состояние экрана теперь сохраняется при поворотах устройства и смене конфигураций.
* Масштабируемость: Архитектура позволяет легко добавлять новые функции (удаление, фильтрация), не затрагивая структуру отображения.
