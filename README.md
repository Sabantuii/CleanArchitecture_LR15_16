# Отчет по ЛР №25: Тестирование

### 1. Объект тестирования
Были выбраны ключевые компоненты архитектуры:
* **UseCase**: Проверка бизнес-логики получения данных.
* **ViewModel**: Проверка корректности изменения состояний (UiState) при различных сценариях.

### 2. Виды тестов
* **Unit-тесты**: Использованы для проверки GetTasksUseCase в изоляции от Android-системы.
* **Интеграционные тесты (базовые)**: Проверка взаимодействия ViewModel с UseCase с использованием UnconfinedTestDispatcher.

### 3. Сценарии покрытия
1. Успешное получение списка задач: проверяется, что isLoading меняется на false, а список tasks заполняется данными.
2. Обработка ошибок: (опционально) проверка появления текста ошибки в uiState при провале запроса.
3. Добавление задачи: проверка вызова addTaskUseCase и последующего обновления списка.

### 4. Выводы
Написание тестов позволило убедиться, что архитектура MVVM, реализованная в ЛР 21, действительно независима. Использование Fake -объектов и MockK позволило протестировать логику приложения без реальных сетевых запросов, что делает процесс разработки более надежным.
